## 一、数据加载自查

### 1.1 线上数据文件可达性

`https://hsr.sightlab.live/data/*.json` 全部 200 OK：

| 文件 | HTTP 状态 | 体积 |
|---|---|---|
| build_summary.json | 200 | 397 B |
| stats.json | 200 | 403 B |
| entities.json | 200 | 1,200,092 B (1.14 MB) |
| relations.json | 200 | 221,948 B |
| events.json | 200 | 43,806 B |
| discrepancies.json | 200 | 22,879 B |
| citations.json | 200 | 280,979 B |

### 1.2 问题根因

**线上页面完全正常。** 无头 Chrome 渲染 live site 结果：
- `loadingEl: false` — 数据已加载完毕
- 状态芯片：`pass1-only 数据`、`未归并实体 1079`、`时间轴推断 44`、`无跨卷矛盾`
- SVG 渲染：`[d3-force 关系图 — 1079 节点, 200 边]`
- 时间轴切换到「银河编年史」后完整渲染 44 个事件
- **控制台 0 错误**

**根因：SiteApp 的初始 SSR 状态为「正在加载数据…」**。数据通过客户端 `fetch()` 加载，SSR（无 JS 环境）只会输出加载状态。用户的抓取工具不执行 JavaScript，看到的就是这个 SSR 占位文本。

### 1.3 修复措施

- 在 `index.astro` 添加 `<noscript>` 块，向无 JS 用户说明需要启用 JavaScript
- 加载态增加 spinner 动画，视觉上更明确是等待状态
- 数据文件已确认全部可访问，无需额外修复

## 四、引证展示显性化

### 4.1 CitationBadge 组件

新建通用组件 `src/components/CitationBadge.jsx`：
- 在所有模型结论旁渲染一个可点击引证徽章（`¶ cite_id` 按钮）
- 点击弹出 popup，并排展示：
  - **结论文本**：模型生成的文字摘要
  - **原文引用**：`「原文片段」`
  - **cite_id**：可定位到游戏文本的 ID
  - **所属卷**：来源卷名
- 点击区域外自动关闭

### 4.2 三个视图的集成

| 视图 | 集成方式 | 验证结果 |
|---|---|---|
| 命途星图 | 图下方「实体引证面板」列出前 20 个实体，每个带 summary + 引证徽章 | 20 个 cite-badge 渲染 |
| 银河编年史 | 每个事件卡片标题旁带引证徽章，点击查看事件描述 ↔ 原文引用 | 44 个 cite-badge 渲染（每事件一个） |
| 矛盾档案 | 左右两侧陈述卡片均带原文引用行（「原文：…」），分析段带 CitationBadge | 20 个矛盾卡片内原文显示 |

矛盾对照视图原本就各带 cite_id，此次增加了原文 quote 文本的直接展示以及分析段的可点击引证弹窗。
